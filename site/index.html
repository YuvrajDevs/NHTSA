Vehicle Safety Intelligence

A governed data product on public US road-safety data: 2.3 million consumer complaints, every recall since 1967 and every defect investigation since 1972, refreshed daily from NHTSA. It answers one question: which components are trending toward a recall, and could complaints have warned us before past recalls?

How data flows

NHTSA publishes full files every day. Bronze keeps every line as received, silver works out what changed since yesterday, gold is a star schema in SQL, and nothing reaches consumers before the data contracts pass. Airflow runs it daily.

Could complaints have warned us before recalls?

For every vehicle recall since 2000: did people complain about the same make, model, year and component system in the 3 years before, and did a simple spike rule (a month with 3× the usual complaints) fire first?

The numbers

Big recalls almost always have complaints beforehand. The simple spike rule catches about a quarter of them, typically about a year ahead. A better signal is a planned next step.

Data contracts

First run blocked the pipeline on 6 real issues in NHTSA's data (undocumented codes, malformed ids, investigations closed before they opened...). Each was investigated and the decision written into the contract. Reconciliation also caught a bug that had silently dropped 35,423 rows (a NULL in a join key).

Data catalog (generated, never hand-written)

Descriptions, owners, grain and personal-data tags come from the contracts; rows and versions from Delta; lineage is parsed from the SQL. Click a table.

Performance

The daily update changes a few hundred of 2.3 million rows, but a Delta MERGE rewrites every data file that holds a changed row: here, all of them. Doing inserts, updates and soft deletes in one MERGE instead of two halves the work. Measured from Delta's own transaction log.
